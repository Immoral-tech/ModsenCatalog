Консольное приложение: ModsenCatalog
1. Общее описание
Задача приложения: консольное приложение реализует администрирование товарного каталога с разграничением прав доступа на основе ролей и полной поддержкой CRUD операций над сущностями.

2. Описание сущностей
2.1 User
Представляет пользователя системы:

Id — уникальный идентификатор (Guid или int).
Username — уникальное имя пользователя.
Email — электронная почта.
PasswordHash — хеш пароля.
Role — роль (Admin, Manager, Customer).
CreatedAt — дата регистрации.
2.2 Category
Представляет категорию товара:

Id — уникальный идентификатор.
Name — уникальное название категории.
Description — описание категории.
2.3 Product
Представляет продукт в системе:

Id — уникальный идентификатор.
Name — название товара.
Description — описание товара.
Price — цена продукта (decimal).
AverageRating — средний рейтинг (рассчитывается автоматически на основе Review).
CategoryId — внешний ключ на категорию.
Category — навигационное свойство.
CreatedAt — дата добавления товара.
2.4 Review
Представляет отзыв и рейтинг пользователя на товар:

Id — уникальный идентификатор.
Rating — оценка (целое число от 1 до 5).
Comment — текст отзыва.
UserId — идентификатор автора.
ProductId — идентификатор товара.
CreatedAt — дата создания.
3. Функциональные требования
3.1 Аутентификация и авторизация
При запуске приложения пользователь вводит логин и пароль.
Система проверяет учетные данные и открывает доступ к меню, соответствующему роли.
Сессия пользователя активна до явного выхода или завершения программы.
Роли определяют доступ к командам:
Admin — полный доступ ко всем функциям, включая управление пользователями.
Manager — управление товарами, категориями, просмотр отзывов.
Customer — просмотр товаров, управление собственными отзывами.
3.2 Управление пользователями (только Admin)
Добавление нового пользователя.
Редактирование данных пользователя.
Удаление пользователя.
Просмотр списка всех пользователей.
Смена роли пользователя.
3.3 Управление категориями (Admin и Manager)
Создание категории с уникальным названием.
Редактирование категории.
Удаление категории (разрешено только в том случае, если в ней нет товаров).
Просмотр всех категорий.
3.4 Управление товарами (Admin и Manager)
Добавление товара.
Редактирование товара.
Удаление товара (связанные отзывы удаляются каскадно).
Просмотр всех товаров с пагинацией в консоли.
Просмотр товара по ID.
Регистронезависимый поиск товаров по названию.
Фильтрация товаров: по категории, по диапазону цен, по минимальному рейтингу.
Сортировка при выводе: по цене (возрастание/убывание), по дате добавления, по среднему рейтингу.
3.5 Управление отзывами и рейтингом (Customer и выше)
Авторизованный пользователь может оставить только один отзыв на конкретный товар.
Редактирование своего отзыва.
Удаление своего отзыва.
Просмотр всех отзывов на товар с поддержкой пагинации.
При добавлении/изменении/удалении отзыва бизнес-логика должна инициировать пересчет AverageRating у товара.
3.6 Работа с консолью
Меню отображается в зависимости от роли текущего пользователя.
Навигация по меню: выбор пунктов цифрами/символами.
Пагинация при выводе списков (товаров, отзывов).
Чтение ввода с валидацией типов данных и повторным запросом при ошибке.
Цветовое оформление (ошибки — красным, успех — зеленым, информационные сообщения — желтым/синим).
3.7 Работа с событиями (In-Memory Event Publishing)
Бизнес-логика должна публиковать события, на которые подписываются обработчики:

PriceChangedEvent — возникает при изменении цены товара: выводит в консоль старую и новую цену.
ProductDeletedEvent — возникает при удалении товара: выводит сообщение «Продукт [Название] удален».
ReviewAddedEvent / ReviewDeletedEvent — выводит в консоль «Спасибо за отзыв!» или «Ваш отзыв удален» соответственно.
UserRoleChangedEvent — выводит в консоль для Admin: «Роль пользователя X изменена с Y на Z».
UserLoggedInEvent — возникает при входе: выводит приветствие «Добро пожаловать, X!».
CategoryDeletedEvent — возникает после успешного удаления категории: выводит «Категория X удалена».
4. Нефункциональные требования
4.1 Архитектура
Использовать N-layer Architecture (Минимум: Presentation, Business Logic, Data Access) или Clean Architecture.
Все зависимости внедряются через встроенный Microsoft.Extensions.DependencyInjection (DI).
Соблюдение принципов SOLID, DRY, KISS, YAGNI.
4.2 База данных
Использовать реляционную БД (SQLite, PostgreSQL или MS SQL).
Использовать Entity Framework Core в качестве ORM.
Конфигурация сущностей (ограничения, индексы, связи) должна быть описана через Fluent API в DbContext (отдельно от сущностей).
Пароли должны храниться в захешированном виде (использовать BCrypt.Net или Microsoft.AspNetCore.Identity.PasswordHasher).
4.3 Обработка ошибок
Глобальный перехват исключений (Try-Catch блок на уровне Program.cs или главного цикла приложения).
Пользователь должен видеть понятное сообщение об ошибке. StackTrace в консоль выводиться не должен.
4.4 Процесс разработки
Разработка в Git, использование feature-веток.
Соблюдение спецификации Conventional Commits.
Наличие README.md с инструкцией по миграциям и запуску через Docker Compose.
4.5 Паттерны публикации событий
Реализовать класс EventPublisher (издатель событий), содержащий подписки на события из п. 3.7.
EventPublisher регистрируется в DI как Singleton.
Обработчики (Handlers) регистрируются в DI, а подписка на события EventPublisher происходит при старте приложения в Program.cs.
4.6 Маппинг
Преобразование между Entity и DTO/ViewModel выполняется с помощью AutoMapper.
Настройки маппинга группируются в классы, унаследованные от Profile (AutoMapper Profiles).
5. Вариативность
Вариант	Стек хранения данных	Дополнительное требование 1	Дополнительное требование 2	Обязательный паттерн
I.	PostgreSQL (через EF Core)	Мягкое удаление (Soft Delete): Пользователи и товары не удаляются физически, а помечаются флагом IsDeleted.	История цен: При изменении цены товара старая цена с датой изменения сохраняется в отдельную таблицу.	Command (Команда): Каждое действие в меню консоли инкапсулировано в отдельный класс команды.
II.	MS SQL Server (через Dapper)	Блокировка пользователей: После 3 неудачных попыток ввода пароля учетная запись пользователя временно блокируется.	Архивация категорий: При удалении категории все её товары автоматически переносятся в дефолтную категорию "Архив".	State (Состояние): Состояние консольного меню (Главное, Админ, Клиент) управляется как автомат состояний.
III.	MongoDB (через официальный драйвер)	Избранное (Favorites): Customer может добавлять товары в персональный список "Избранное" и просматривать его.	Аудит действий: Все критические операции (смена роли, удаление) логируются в коллекцию AuditLogs.	Strategy (Стратегия): Разные алгоритмы сортировки товаров (по цене, рейтингу) реализованы как стратегии.
IV.	JSON-файлы (сохранение на диск)	Промокоды / Скидки: Возможность применить к товару промокод, который снижает его цену при выводе в каталоге.	Статистика для Admin: Вывод отчета: топ-5 самых оцениваемых товаров и самый активный покупатель.	Repository (Репозиторий): Прямая работа с файлами скрыта за абстракцией репозиториев для каждой сущности.
V.	SQLite (через EF Core)	Срок действия отзывов: Отзывы старше 30 дней автоматически скрываются из общего списка и не влияют на средний рейтинг.	Импорт/Экспорт: Возможность выгрузить весь каталог товаров в текстовый файл формата CSV и импортировать обратно.	Chain of Responsibility: Валидация вводимых пользователем данных перед обработкой (пустота, тип, диапазон).
